# 人物卡多个 HTML 面板

## 问题

读取 MVU 是数据访问行为，不是面板用途声明。旧实现把一个读取 MVU 的 iframe 从消息提升为唯一常驻视图，建档页因此可能取代角色状态页。变量结算错误与页面加载失败需要独立诊断。

## 行为

- 通过 StatusPlaceHolderImpl 或 <…-status/> 显示规则声明的可执行面板组成状态栏集合；每个模板有独立标识，按标签切换，隐藏而不卸载。
- 其他可执行 HTML 保留在原消息；使用者可固定至右侧或返回消息。读取 MVU 不再自动迁移页面。
- 手动固定移动已有页面节点，必须使用浏览器支持的保留状态移动 API；不通过复制或重新设置 srcdoc 实现。原消息卸载、会话切换时释放固定关系。
- 当前标签切换和变量变化不重建 iframe；模板改变、会话改变或用户点击刷新时才重建。只在 load 时读取数据的旧卡没有更新订阅，数据同步后需手动刷新当前面板才能重绘；不猜测卡片私有的刷新函数。保留原有变量作用域与写入版本校验。
- 面板运行日志保留来源轮次、片段与模板身份；加载和交互错误使用已有采集渠道。

## 验证

以命定之诗与赛博朋克红卡片为实际样本，覆盖建档不自动迁移、多状态模板、标签切换、固定/返回时输入和 iframe 身份不变、切换会话清理。单元检查与浏览器结果分别报告。

## 本次验证结果

- PNG 元数据为“赛博朋克红·夜城GM”，去掉变量初始化并统一换行后，开场白与诊断包相同。
- Chromium 实际加载卡片的建档 HTML 与状态 HTML，使用生产 React 组件和 Helper 桥接、受控变量数据：建档输入、固定、标签切换、返回、变量上下文同步、手动刷新、会话切换通过；无页面异常。
- 此验证不是群友 Windows DSH 上的完整剧情生成，也没有复现或修复日志里的独立 MVU 提交失败。
- 固定使用 Element.moveBefore 保留浏览上下文；旧浏览器没有该能力时保留原页面并给出明确提示。

- 187 项相关测试通过；全量运行发现的 6 项旧失败在独立基线检出复现（helper-module-loading 4 项、mvu-background-settlement 1 项、story-ledger 1 项），未混入本次修复。
