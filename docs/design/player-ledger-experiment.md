# 玩家台账维护实验

分支：`experiment/background-ledger`。日期：2026-09-09。

## 行为约定

- 台账是给玩家看的备忘录。**不注入前台提示词，不修改正文、人物卡变量或候选提示词。** 后台读取旧台账，仅用于整理增量与避免重复记账。
- 在设置 → 后台任务开启“台账维护（实验）”，默认关闭。对当前及新游戏的后续结算生效，不要求新开对话，也不自动补齐旧剧情。
- 同一个后台 Agent、同一次 settlement 模型任务增加 `ledger_submit`，不是新增子 Agent 或每类台账单独调用模型。普通卡和 MVU 卡均接入；MVU 暂存执行恢复时复用已保存状态，不重复累加台账。
- 本轮先提交台账，再提交姿势或 MVU 变量。台账没变化也提交空对象；无效参数可修正，已接受的同任务重复调用不重复入账。
- 开启会增加后台输入、输出和工具调用；台账提取失败沿用后台结算的错误与重试入口。关闭后保留已有记录，停止自动维护。

## 借鉴柏宝书的部分

参考版本、源码链接和完整分析见 [台账研究](../research/baibai-book-ledger-2026-09-09.md)。没有引入其运行时、摘要森林、向量库或前台注入机制。

| 分类 | 沿用的语义与界面 |
| --- | --- |
| 物品 | 名称、数量、描述、随身/寄存地点；add 数量累加、update 数量覆盖、remove 移除；列表和最近八笔变动 |
| 角色 | 身份、关系、外貌性格、当前穿着状态、主要角色、随行与地点；分主要角色/在场/同区域/不在场显示 |
| 地点 | 从大到小的路径、描述、当前位置；折叠树与寄存物品；支持子树改名/迁移 |

采用有筛选的提取规则：只登记有意义的物品、重要互动人物、具体地点；不盘点全部路人和环境物件。复用已有名称，不将一次友善等同关系质变。第一版不做计划悬念、自定义变量、旅行草稿和关系图，也不对离场人物做推演。

## 存储与回退

`chat.ledger` 保存当前台账，接入原生 Story Timeline 的快照和恢复；不另造一份 ST 式消息历史。后台完成通过已有 coordinator 的 branch/revision 校验才写入；撤回或分支已变化时，迟到结果作废。旧 checkpoint 没有台账时恢复为空。

手动添加、修改、删除也通过 Chat 更新和 `ledger.edit` 时间线事件提交，不写前台 Session；生成、回退或后台处理中不允许编辑，旧编辑结果与当前台账不一致时拒绝保存。手动修正随所在剧情状态回退。普通正文编辑不会重新推断台账，改变剧情事实后应手动核对。

物品和人物按规范化名称匹配，地点按路径匹配；这与柏宝书一样不构成完整实体消歧，不支持以独立 owner 区分多人同名库存。提取准确率仍由模型和正文明确程度决定。

## 试用与安全退出

1. 切到实验分支，重启 Tavern 并刷新浏览器。
2. 在后台任务设置开启台账维护，正常推进一轮，等后台结算完成。
3. 右侧“游玩台账”点查看，切换物品、角色、地点；可手动纠错。
4. 回退并重新生成，核对旧数量、人物和地点是否恢复，再查看新一轮的更新。
5. 不想继续使用时关闭开关。整个实验只在此分支提交，未合并或发布；切回 main 并重启即可恢复原版功能。main 不使用台账字段，已有存档正文无需转换。

## 已验证范围

- 自动化测试：增删改、重复提交、无效输入不落盘、地点子树迁移、旧编辑拒绝、生成中禁止手改。
- 真实普通卡 runSettlement 调用路径和 MVU 模块，用假模型验证同一后台任务提交台账及完成顺序。
- Story Timeline 回退和迟到结果隔离；前台 Frame 中不出现台账数据。
- 独立浏览器样例加载生产 React 组件：展开、修改数量、角色分组、地点树及 390px 布局。没有操作用户存档。
- 尚未调用真实模型验证跨人物卡提取质量，也未在完整 Tavern 服务内完成一轮实机游玩。
