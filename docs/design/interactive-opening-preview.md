# 交互式开场预览

## 问题与实现

部分人物卡用正则将默认开场的占位文字替换为 HTML 首页，包含视频、音乐和人物选择。选择脚本读取第 0 条消息的 swipes，再调用 setChatMessage 或 setChatMessages 切换开场。此前预览会整体过滤等待 MVU 的正则替换，导致首页消失；普通列表归一化还会删除备用开场的空槽和重复项，破坏脚本索引。

预览保留读取聊天并切换开场、且不直接访问 Mvu 数据的首页规则。仅等待 waitGlobalInitialized('Mvu') 不再让整个首页被过滤；真正依赖 Mvu 数据的状态 UI 仍留到正式开局后初始化。其他普通预览行为保持不变。

客户端使用独立的开场选择桥接，不提供正式聊天的 Helper 写入通道。getChatMessages('0') 返回人物卡原始开场槽位；setChatMessage(text, 0, {swipe_id}) 和单条 setChatMessages 补丁只能选择已有、非空的开场。自定义正文、变量补丁和无效索引报错。页面选择映射到原生 openingId，玩家确认“开始新游戏”后仍走现有开局流程；预热机制保持不变，预览点击本身不提交开场或初始化 MVU。

消息来源、当前 iframe token 和当前文档均需匹配，切卡或卸载后的旧页面不能触发新开场选择。HTML 中的脚本无需改写，媒体使用已有 iframe 渲染，音视频源由浏览器直接加载，封面等静态资源继续代理。音乐、有声视频的自动播放仍受浏览器策略限制，不承诺绕过浏览器播放限制。

备用开场不再按标签列表去重、去空或 trim；显示列表可跳过空项，但 openingId 保留原始位置。旧版工作区迁移仍按旧归一化算法比较基线，以免把过去的自动去重误认为玩家编辑。

## 验证（2026-09-07）

- 原始「岁岁年年」人物卡静态投影：视频、首页脚本及 7 个开场索引保留；未执行私人卡的故事或外部脚本。
- 合成人物卡真实浏览器：视频 readyState=4、paused=false；首页按钮通过原始 swipe 2 切换到原生 alternate:1（中间有空槽），界面显示 2/2；确认开局后正式会话只使用选定的海边正文。
- 回归覆盖普通预览、MVU 状态 UI 隔离、单数/复数选择接口、空槽、重复开场、旧工作区迁移、非法修改拒绝、iframe 来源与过期文档校验。没有通过该桥接调用 Session RPC。

合成卡正式开局后还出现 MVU 初始化未保存提示；本次只验证选定正文的提交，不据此承诺原卡后续 MVU 结算兼容。

最终全套测试 1653 项通过，0 失败、0 跳过；生成客户端一致性检查通过。


## 原卡大视频补充修正

原卡视频为 152,498,195 字节，超过静态缓存 64 MiB 的单文件上限；原代理返回缓存超限错误，浏览器呈现 0:00 黑屏。此前 data URI 合成视频没有覆盖这条远程缓存路径。

音视频及 source 元素的 src 保留原始远端 URL，不再进入整文件缓存。处理覆盖初始 HTML、缓存 HTML 的相对资源地址、动态 src 属性、setAttribute 及属性观察器；封面、图片、脚本仍使用原缓存。浏览器原生负责媒体加载、Range 请求及拖动播放。

实际原卡 iframe 验证：视频 readyState=4、paused=false、currentTime=17.89 秒，时长 71.40 秒，画面 1080×1920。未切换角色或发送故事请求。
